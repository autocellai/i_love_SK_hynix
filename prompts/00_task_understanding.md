# 00. 과제 파악 및 범위 정의

## 목적

과제의 실제 요구사항, 제출물, 평가 기준, 제약을 먼저 구분합니다. 이 단계에서는 원칙적으로 데이터와 코드를 수정하지 않습니다.

## 프롬프트

```text
과제 안내와 현재 작업공간을 확인해줘. 아직 파일이나 데이터를 수정하지 마.

다음 항목을 정리해줘.
1. 해결해야 할 문제를 한 문장으로 표현
2. 과제에서 명시한 필수 요구사항
3. 선택 또는 개선 가능 요구사항
4. 제출물의 형식·파일명·필수 내용·제출 위치
5. 제공 파일과 각 파일의 역할
6. 시간, 도구, 보안상 제약
7. 안내문만으로는 알 수 없어 확인이 필요한 사항

명시된 내용과 네가 추론한 내용을 분리하고,
가능하면 근거가 되는 문서명·페이지·파일 경로를 표시해줘.
```

## 결과 기록 형식

| 구분 | 내용 | 근거/상태 |
|---|---|---|
| 핵심 문제 | {문제} | 명시/해석 |
| 필수 제출물 | {파일·형식} | 명시 |
| 데이터 | {파일 목록} | 확인 |
| 제한 조건 | {시간·도구·보안} | 명시 |
| 확인 필요 | {불명확한 사항} | 미확인 |

## 유의사항

- 문제에서 요구하지 않은 기능을 임의로 추가하지 않습니다.
- 요구사항이 불명확할 때는 확인 질문을 합니다. 질문이 불가능한 상황에서는 가정과 결과 영향을 명시합니다.
- 작업공간의 기존 `README.md`, `AGENTS.md`, 과제 지시사항을 우선합니다.
