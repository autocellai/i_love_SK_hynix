# 06. 오류 분석 및 디버깅

## 프롬프트: 원인 파악

```text
다음 문제가 발생했어.
증상: {증상}
재현 단계: {명령 또는 동작}
에러 메시지: {핵심 메시지}
기대 동작: {기대 결과}

바로 코드를 수정하지 말고,
1. 가능한 원인 후보
2. 각 원인을 확인할 최소 점검
3. 가장 가능성 높은 원인과 근거
4. 수정 범위와 위험
을 먼저 제시해줘.
```

## 같은 실패가 반복될 때

```text
같은 접근을 두 번 시도했지만 해결되지 않았어.
1. 지금까지의 시도와 관찰된 결과를 요약
2. 최소 재현 조건으로 범위 축소
3. 기존 가설이 틀렸을 가능성 검토
4. 다른 접근 2가지와 장단점 제시
코드 변경 전 계획을 먼저 보여줘.
```

## 로그·에러 출력 원칙

- 민감한 경로, 토큰, 개인정보, 원본 데이터 행을 불필요하게 출력하지 않습니다.
- 에러 메시지는 원인 파악에 필요한 최소 부분만 확인합니다.
- 보안 모니터링·감독·업로드 제한 관련 오류는 우회하지 않고 공식 신고·지원 절차를 따릅니다.
- 확인하지 않은 원인을 확정적으로 말하지 않습니다.
